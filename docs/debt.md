# Known gaps

One entry per gap: what differs from the contract or is unverified, and where. A change that closes a gap removes its entry.

- **Unity code lifecycle.** When the minimum Unity version reaches 6000.5, move the three lifecycle hooks in `package/Runtime/UgoHTTP.Unity/Lifetime.cs`: `beforeAssemblyReload` to `[OnCodeUnloading]`, `ExitingEditMode` to `[OnExitingEditMode]` and `EnteredEditMode` to `[OnEnteringEditMode]`. The newer attributes support future scripting runtimes; they are unavailable at the current 6000.3 floor. Unity 7.0's CoreCLR Editor has no domain reload on entering Play Mode, permits static constructors to run lazily and off the main thread, and has not documented how `[InitializeOnLoad]` behaves. Add a `#if UNITY_6000_5_OR_NEWER` branch for these attributes only once a 6000.5+ Editor is in the test matrix; adding it earlier would ship untested code.
- **Windows symbols.** No crash symbols: the build uses `-g0` and strips. zig 0.17.1 does emit CodeView and a `.pdb` for `x86_64-windows-gnu` with `-g` (checked on a test DLL; `aarch64-windows-gnu` not checked), so a symbol file archived next to each release is possible but not wired.
- **Progress totals.** `receive_total`/`send_total` are -1 when curl reports 0, so a known zero length reads as unknown.
- **Connection reuse flag** is derived (`NUM_CONNECTS == 0 && CONN_ID >= 0`); across redirects, a 303 re-issue included, it means no hop opened a new connection.
- **Fatal `CURLMcode`** finishes every transfer `INTERNAL` and leaves the client broken; untested, no injection point.
- **Sanitizer coverage on macOS.** LSan is unsupported on arm64 macOS and deps are not TSan-instrumented there; leak and full TSan coverage come from the container runs.
- **Managed runtime coverage.** IL2CPP layout checked on Android arm64-v8a and the iOS arm64 simulator only (armeabi-v7a, Android x86_64, iOS device and x86_64-simulator players not built). Large-file offsets on armv7 are guarded by `verify` only, never run on a 32-bit device. No test performs a real quit: the EditMode test invokes the handler registered on `EditorApplication.quitting`, and the player hook (`Application.quitting` from `Lifetime.Install`) is shown to survive stripping only by a UnityLinker run, never executed in a player. At domain reload or `Dispose` with no drain running, completions of raw `Submit` operations are drained and dropped: there is no consumer to hand them to.
- **No PIPEWAIT.** Parallel requests to a host with no settled connection yet each open their own connection (no `CURLOPT_PIPEWAIT`, see decisions.md *No PIPEWAIT*). Fix belongs in curl: a PIPEWAIT transfer is not woken after the connection settles on HTTP/1.1.
- **The first client costs about 1 MiB RSS, mostly library code.** In the benchmark app on a Xiaomi 24129PN74G, creating the first UgoHTTP client grew RSS by 896–1,280 KiB; UnityWebRequest showed no growth, its code being in the already resident `libunity.so`. The figure includes loading `libugo.so`: IL2CPP loads a plugin on its first P/Invoke, here `ugo_shutdown_all` in the `UgoClient` constructor. A native probe (`dlopen` of the release `libugo.so`, then `ugo_client_create` four times, `/proc/self/smaps` after each step) on the same Xiaomi, `max_transfers` 16, split it: `dlopen` +304 KiB (288 of them `libugo.so` pages), the first call +64 KiB, the first client +684 KiB (576 `libugo.so` pages, 92 heap, 12 thread stack), each further client +52–84 KiB (heap and 12 KiB stack); with `max_transfers` 64 the first client +804 KiB, each further one +110–130 KiB. A Pixel 7a gave the same within 40 KiB. So about 930 KiB is a once-per-process cost of mapped library pages, of which 40 KiB is dirty (relro, `.data`, `.bss`); the rest are clean file pages the kernel can reclaim. `/proc/self/pagemap` after the first client shows all of `.text` (627 KiB) resident although one client creation runs a small part of it; `MADV_RANDOM` on the mappings changed nothing, which fits the kernel's fault-around mapping cached neighbours of each faulting page (unconfirmed: `fault_around_bytes` needs root). The CA bundle (200 KiB of `.rodata`) stays unmapped: it is parsed at the first TLS connection (`on_ssl_ctx`), not at creation. Per client the native heap holds `struct client` (18 KiB, 16 KiB of it the WebSocket drop buffer `drop[WS_DROP_BYTES]`, present even if no socket is ever opened), about 1 KiB per slot (`struct slot` is 944 bytes) and about 25–40 KiB for the curl multi handle and allocator state of the new thread, not split further. Open: allocating the drop buffer only with the first WebSocket would save 16 KiB per client. After creation, eight parallel 2 MiB downloads over HTTP/2 and 3 s idle grew RSS by a median of 352 KiB for UgoHTTP against 820 KiB for UnityWebRequest (README *Benchmarks*).
- **Platforms run only partly.** iOS device arm64 and simulator x86_64 slices are built and verified statically (exports, symbol privacy, linked size), never run. macOS x86_64 is smoke-probed under Rosetta, Linux x86_64 under emulated `linux/amd64` docker; no macOS or Linux standalone player is built (the Editor loads `ugo.bundle` on arm64 only). Linux ARM64 is loaded by nothing Unity ships: 6000.3 has no Linux ARM64 Editor or player, so its importer setting is untested. The bundle is ad-hoc signed; signing and notarization of a standalone build with an app's own signing identity are untested.
- **iOS device player runs only under a debugger.** `tests/ios/run --device` passes every check on an iPhone 8 with iOS 16.7.12 (LAN bench, self-opened Settings, the background task finishing and expiring at about 26 s), but always with lldb attached through `ios-deploy`: a debugged app is never suspended, so the suspension after expiry and the return from it are not exercised on a device. Built with Xcode 26.2, outside the `XCODE_VERSION` pin.
- **iOS background expiry under host load.** On an overloaded Mac (load average 130–300 on 16 cores) the simulator's runningboardd fires its expiry warning late or delivers it to the player late (up to 11 s), so the player gets it at or after the expiry instead of 5 s before; UIKit runs no expiration handler until then, and runningboardd kills the player `0x2182BAD2` ("Timed-out waiting for process … to invalidate assertion … 'Shared Background Assertion'") even when the handler ends the task within milliseconds of being called. Seen in 5 of 12 runs on 2026-11-05, as often without `background_detached_post` as with it. `tests/ios/run` reruns such attempts; a device under load is not checked.
- **Windows host coverage.** On a Windows x64 host `windows-arm64` gets static checks only (PE machine, exports, imports, no crypto instructions, archive version strings): under Docker Desktop's QEMU user emulation, Wine arm64 runs stock binaries such as `cmd.exe` but `ugo-smoke.exe` faults on a null pointer stored by its CRT startup (`str wzr, [x8]`), and `wineboot` segfaults while the image is built. Not diagnosed, and the same binary on an arm64 Mac is not compared. `unity-editmode` on Windows has not run yet: its Windows bench start and stop in `tests/unity/Assets/Tests/Editor/Bench.cs` are unexercised.
- **iOS frameworks.** The XCFramework's importer declares `CoreFoundation` and `UIKit` (all `libugo.a` needs beyond libSystem/libobjc); checked with Unity 6000.3's generated project only.
- **curl buffers a burst outside the backlog.** `curl_ws_recv` refills its receive buffer only when empty and then keeps reading while each read fills a whole 64 KiB chunk (a soft-limited `bufq`, `lib/ws.c` and `lib/bufq.c` at `curl-8_23_0`). A paused socket reads nothing, but the read that precedes a pause can pull everything the kernel holds into curl's memory; the extra chunks are freed as they are consumed. The TCP receive window does not bound it: each consumed chunk reopens the window, so a producer that keeps up with the reads keeps the read going. Fix belongs in curl (a hard limit for the WebSocket receive buffer).
- **Framing errors close without CLOSE.** Errors found by curl's frame decoder (masked frame, reserved bits or opcode, oversized or fragmented control frame, broken fragment sequence) end the socket as `TRANSFER`/1006 instead of sending CLOSE 1002 (RFC 6455 §7.1.7 SHOULD). curl's encoder would still send one, but `curl_ws_recv` returns `CURLE_RECV_ERROR` both for a decoder error and for a failed socket read (`ws_dec_pass` and `nw_in_recv` in `lib/ws.c` at `curl-8_23_0`); only the error-buffer text (`[WS] …`) tells them apart, and the shim does not classify by curl's message text. Fix belongs in curl (a distinct code for a protocol error), or in the shim parsing frames itself in `CURLWS_RAW_MODE`. Errors the shim finds itself (UTF-8, size, bad CLOSE) do send their code and stop reading.
- **Patched mbedTLS: four-block AESCE GCM.** `native/deps/patches/mbedtls-4.1.1-aesce-gcm-4block.patch` (patches.md) is a cut-down port of unmerged upstream code (TF-PSA-Crypto PR #702). It keeps H^2..H^4 in rows of `ctx->H` that the AESCE multiply does not read in 1.1.1; a release that changes that layout without touching the patched hunks applies cleanly. The gate checks the kernel against fixed outputs only where `aes_gcm_known_answers` runs (macOS arm64, Linux arm64 container); Android and iOS exercise it only through TLS against the bench. Not built: big-endian AArch64, `MBEDTLS_GCM_LARGE_TABLE`; a PSA AES driver (`MBEDTLS_BLOCK_CIPHER_SOME_PSA`) compiles the patch out. At `-Os` one H-power operand spills to the stack and is not zeroized; the stock code keeps H only in the context.
- **Resume checked against the bench only.** `UGO_REQ_RESUME` is tested against the fault bench's `/range` endpoint (HTTP/1.1, HTTP/2, players); no CDN or production origin (short `206` answers, `If-Range` with `Last-Modified`, compressed-at-rest objects) has been run.
- **WebSocket soak covers one steady path.** `tests/ios/run --soak` keeps the app in the foreground on a steady LAN with lldb attached: no backgrounding or suspension during a soak, no screen lock, no Wi-Fi to cellular switch or address change, no server-side drop (a drop fails the run; reconnect is the caller's). iPhone only: no Android device or emulator soak. IL2CPP has no per-thread allocation counter (`GC.GetAllocatedBytesForCurrentThread` gives nothing usable in the player), so no allocation per message is shown only by the GC count staying at the minute's own collections with a flat heap.
- **Tracker window checked by hand only in part.** Clicking a stack link (the Editor opening the file at the line) and dragging the splitter are not automated; EditMode tests check the link markup and the serialized split fraction. A Play Mode exit with domain reload on clears the tracker's history with the other statics, so the leak marks survive only when the next reload has not happened yet.
- **TLS failures checked below the library.** Expired, wrong-hostname and incomplete-chain certificates are checked by the bench selftest with the system `curl` only; `libugo` sees an untrusted root and a broken CA bundle (native) and a self-signed certificate (players), not these. Revocation is not tested.
- **408/429 with `Retry-After` not checked through the library.** The bench serves them and its selftest checks them with the system `curl`; no native or managed test checks that the status and the `Retry-After` header reach the caller.
- **Event timestamps across app pause not tested.** The native test checks the monotonic clock across a 20 ms sleep only; no player test compares event timestamps on both sides of a background/foreground cycle.
- **Slow connect not checked through the library.** The container injects it, but only its selftest (system `curl`) runs against it.
- **curl re-sends non-idempotent requests.** On a reused connection that died before any response byte curl re-sends the request on a fresh connection whatever the method, POST included (`Curl_retry_request`, `lib/transfer.c` at `curl-8_23_0`, up to 5 times); RFC 9112 §9.3.1 forbids automatic retries of non-idempotent requests unless the client knows the request was not applied. The `REFUSED_STREAM`/GOAWAY retry is safe: the server states it did not process the stream. No option turns the first off short of `CURLOPT_FRESH_CONNECT`.
