# C ABI v2

The contract of `native/include/ugo.h`. `native/abi/layout_check.c` holds the expected sizes and offsets as `_Static_assert`s (the source of truth) and, built with `-DUGO_LAYOUT_PRINT`, dumps them plus every constant. `UgoAbi.Dump()` in `package/Runtime/UgoHTTP/UgoAbi.cs` produces the same lines by reflection (`Marshal.SizeOf`, `Marshal.OffsetOf` over fields in declaration order, `sizeof(T)` for the array stride, const fields); the gate diffs the two dumps on every runtime.

## Conventions

- Functions return `int32_t`: `UGO_OK` (0), a negative `UGO_E_*`, or a count ≥ 0 (`wait`). A failing call changes nothing.
- An id is `generation << 32 | slot`; generation starts at 1, so `0` (`UGO_INVALID_ID`) is never valid. A slot whose generation would wrap is retired, never reused: an old id never turns live again; the client loses one slot per 2^32 − 1 reuses of it. `slot < max_transfers`: the caller may index its own array with it.
- Text and bytes are `ugo_bytes {ptr, len}`; text is UTF-8, never NUL-terminated. `ptr == 0` is allowed only with `len == 0`.
- Enum-valued fields are `uint32_t`; `reserved` fields and unknown flag bits must be 0, else `UGO_E_INVALID_ARG`.
- Times are microseconds. Event `time_us` and `ugo_monotonic_us()` read the same monotonic clock, which keeps counting while the system sleeps: Linux/Android `CLOCK_BOOTTIME`, Apple `mach_continuous_time`, Windows `QueryInterruptTime`. Phase timings are curl's `*_TIME_T` (µs from transfer start, 0 = phase not reached) on curl's own clock, which on some platforms stops during sleep.
- `submit` and `ws_open` parse the URL with curl's URL API and hand the parsed handle to curl (`CURLOPT_CURLU`): a malformed URL, or a scheme other than `http`/`https` for `submit` and `ws`/`wss` for `ws_open`, is `E_INVALID_ARG`, never a `completed`.
- `config.abi_version != UGO_ABI_VERSION` → `ugo_client_create` returns `E_ABI`.
- `E_NOMEM`: an allocation or OS resource (thread, wakeup socket) failed in `create`, `submit` or `ws_open`.

## Events

Each slot stores its own pending events: one `headers`, one coalesced `progress` and one `completed` place; a WebSocket slot also has its message backlog, allocated at `ws_open`. A bounded queue of slot indices (≤ `max_transfers` entries, a slot at most once) says which slots have undrained events. There is no event capacity and no reservation: `submit`/`ws_open` fail with `E_CAPACITY` only when no slot is free. Per id, pending events drain in order `headers`, `progress`, `completed` (WebSocket: `headers`, messages by `seq`, `completed`); upload progress may be emitted, and drained, before the response's `headers` exist; order across ids is not defined. After `completed` an id gets no more events.

`progress` is published only when a byte count changed. Intermediate progress updates are published at most once every 10 ms per transfer; a count held by that limit is published before `completed`, regardless of the interval, so the last `progress` carries the final byte counts. An event's `time_us` is when the owner published it, not when it was drained; a held count published at the end carries the completion time.

## Transfer lifecycle (HTTP)

```
submit ─► QUEUED ─owner picks─► RUNNING ─[headers]─► RUNNING ─[completed emitted]─► DONE ─completed drained─► FINISHED ─release─► FREE (id stale)
             └──────────── abort: marked; owner finishes as Aborted ─────────────┘
```

| Call | QUEUED / RUNNING | DONE (`completed` not drained) | FINISHED | FREE / unknown |
|---|---|---|---|---|
| `ugo_abort` | `OK`, marks it; result is `completed(ABORTED)` unless it was already finishing | `OK`, no-op | `OK`, no-op | `E_STALE_ID` |
| `ugo_get_result` | `E_STATE` | `E_STATE` | `OK` | `E_STALE_ID` |
| `ugo_release` | `E_STATE` | `E_STATE` | `OK`, slot freed, generation bumped | `E_STALE_ID` |

- `release` before the `completed` is drained is refused: that event lives in the slot, so freeing it would drop the event or need a tombstone in the index queue.
- `headers` carries the final response's header block (after redirects), lines exactly as curl delivered them (status line, CRLF, blank line; HTTP/2 gets curl's synthesized status line; no trailers). `ugo_result.headers` is the same block if the final response's headers completed, else empty.
- Detached (`UGO_REQ_DETACHED`): `QUEUED → RUNNING → FREE`, no events. `abort` → `OK` until it finishes, `E_STALE_ID` after; `get_result`/`release` → `E_STATE` while running. Memory body and memory parts are copied at `submit`; `sink_path` must be empty and the response body is discarded.
- `UGO_REQ_FINISH_IN_BACKGROUND` (iOS; ignored elsewhere): a background task is held from `submit` to finish and ended exactly once, by whichever of `finish` and the expiration handler runs first. On expiration the transfer is finished as `ABORTED` / `UGO_DETAIL_BACKGROUND_EXPIRED` — best effort: iOS may suspend the process before the owner runs, and after resume the dead connection may surface first as `CONNECT`/`TRANSFER`. If iOS grants no task at `submit`, the flag does nothing and the transfer is suspended with the app. Combines with detached.
- File sink: created (truncated if it exists) on the first body byte of a 2xx final response, or in `finish` for an empty 2xx response, so success always leaves a file holding exactly the body and a non-2xx leaves none of the library's making (a file already at `sink_path` that the library never opened is not touched); closed before `completed`; on any non-success deleted before `completed` unless `UGO_REQ_KEEP_PARTIAL` or `UGO_REQ_RESUME`. An open or write failure is `LOCAL_IO`. The body of a non-2xx final response goes to memory instead, capped at `UGO_ERROR_BODY_MAX` (64 KiB), and is `ugo_result.body`.
- `UGO_REQ_RESUME` (needs `sink_path`; with `HEAD` or a caller `Range` header `E_INVALID_ARG`): when the transfer starts, the owner opens an existing non-empty regular file at `sink_path` without creating or truncating it, and its length `n` becomes the offset; the request then carries `Range: bytes=n-` (on every redirect hop too). No such file (or an empty one): no `Range`, the sink behaves as without the flag. Either way the request carries `Accept-Encoding: identity` unless the caller sent `Accept-Encoding`, and the file is kept on failure. The final response decides, before its body. `206` with exactly one `Content-Range: bytes n-last/total` (or `/*`), not `multipart/byteranges`, and no `Content-Length` other than `last - n + 1` → the body is appended at `n`, held to exactly that range: bytes past it stop the transfer, and a body that ends short of it fails, whatever the framing (`Content-Length`, chunked, close-delimited, HTTP/2). A complete range that ends before a known `total` (a short `206`) is `TRANSFER` with detail `NONE` and the file kept, as a cut connection: the next resume continues from the new length. `416` with exactly one `Content-Range: bytes */n` → `completed` class `NONE`, `http_status` 416, file untouched; the 64 KiB error-body cap still applies to its body, and an overflowing one is `HTTP_STATUS` / `MEMORY_LIMIT`, file untouched. Any other `2xx` → file truncated to 0 and rewritten. Any other non-2xx → file untouched, `HTTP_STATUS`. Every other `206` or `416` → `TRANSFER` / `UGO_DETAIL_RESUME_MISMATCH`, the `headers` event still emitted, the transfer stopped; the file is deleted only when the server contradicts it (a `206` starting elsewhere than `n`, a `416` with a length below `n`) and `UGO_REQ_KEEP_PARTIAL` is not set; otherwise (no, a repeated or a malformed `Content-Range`, multipart, a `Content-Length` or body other than the range, a `416` with no length or a longer one) it is kept with what was written. `headers.resume_offset` is `n` after an appending `206` or a completing `416`, else 0; after an appending `206` `progress.received` includes it and `receive_total` is the `Content-Range` total (its `last + 1` when `*`), so both count the whole file; `completed.bytes_received` counts this transfer only. No validator is kept: `If-Range` is an ordinary caller header, and the server's evaluation of it (a `200` on mismatch) is what restarts a changed resource.
- Memory cap: a body longer than its cap (`memory_limit` for a memory sink, `UGO_ERROR_BODY_MAX` for a non-2xx body of a file sink) aborts the transfer at that point; `ugo_result.body` holds the first cap bytes. The class stays `HTTP_STATUS` for a non-2xx response, else `TRANSFER`; the detail is `UGO_DETAIL_MEMORY_LIMIT`. `memory_limit` is ignored for a file sink.
- Content coding: unless the caller sends an `Accept-Encoding` header or the request has `UGO_REQ_RESUME` (which sends `Accept-Encoding: identity` and is never decoded: ranges count encoded bytes), the request carries `Accept-Encoding: gzip` (`CURLOPT_ACCEPT_ENCODING`) and curl decodes a gzip or deflate response before the shim sees it, on every followed redirect too. The memory cap, the error-body cap, the file sink and `ugo_result.body` hold decoded bytes; the header block (`Content-Encoding`, `Content-Length`), `headers.content_length`, `progress.received`/`receive_total` and `completed.bytes_received` count the bytes on the wire. A body that fails decoding (corrupt data, a coding curl does not know, bytes after the end of the stream) is `TRANSFER`/`NONE` with `curl_code` `CURLE_BAD_CONTENT_ENCODING` (61) or `CURLE_WRITE_ERROR` (23). A stream that ends before its end marker while the HTTP framing is complete is `CURLE_BAD_CONTENT_ENCODING` too (patched curl, decisions.md *curl patch: unfinished content coding*). The file sink has no decoded-size bound: hosts are trusted. With a caller `Accept-Encoding` (an empty or removal line included) no `Content-Encoding` is decoded: the body is delivered as received. Independently of `Accept-Encoding`, chunked framing is always removed, and a `Transfer-Encoding` coding other than chunked (e.g. `gzip`, never requested: `CURLOPT_TRANSFER_ENCODING` is off) is refused as `TRANSFER` / `CURLE_BAD_CONTENT_ENCODING` (61). HEAD, 204 and 304 have no body to decode. Request bodies are never compressed; WebSocket handshakes carry no `Accept-Encoding`.
- Redirects 301, 302, 307 and 308 replay the method and the request body (curl `CURL_REDIR_POST_ALL`; curl keeps `CURLOPT_CUSTOMREQUEST` on redirects). A 303 is followed by the shim: curl resolves its `Location`, checks the scheme and counts the hop, then the shim aborts curl's next request before it is sent (`CURLOPT_PREREQFUNCTION`) and re-issues it on the same handle as GET (HEAD stays HEAD) without a body, without the caller's `Content-Type`, `Content-Length`, `Content-Encoding` and `Transfer-Encoding` lines, and with `Authorization`, `Cookie` and a caller `Host` only when the target has the original scheme, host, port and IPv6 zone ID; later hops are curl's again, so 302 → 303 → 200 and 303 → 302 → 200 both work. `max_redirects` bounds all hops together; past it the transfer is `TRANSFER` / `CURLE_TOO_MANY_REDIRECTS` as for curl's own following. `total_timeout_ms` spans every hop. `redirect_count`, `total_us` and `redirect_us` include the hops before a re-issue; the other phase timings are measured from the start of the last re-issued request, or describe the segment that ended in the 303 when the transfer ends before the re-issued request starts. `connection_reused` is 1 only if no segment opened a connection. On HTTP/1.1 the abort closes the connection curl selected for the next hop (`multi_done`, `lib/multi.c` at `curl-8_23_0`: a non-multiplexed connection after any callback abort), which is the one the 303 came on only when curl picked it again; the re-issued request then takes another connection, new or pooled. On HTTP/2 the connection is kept. A resumed download keeps its `Range` across a 303; a detached request is re-issued the same way.
- `completed.detail` narrows the class: `ABORTED` by `CALLER`, `SHUTDOWN` or `BACKGROUND_EXPIRED`; `TRANSFER` and `HTTP_STATUS` by `MEMORY_LIMIT`; `TRANSFER` by `WS_HANDSHAKE` or `RESUME_MISMATCH`; WebSocket closes by `WS_CLOSED_BY_*`; otherwise `NONE`.

## Methods and request headers

- `method` is the request-line token as sent: 1 to `UGO_METHOD_MAX` (32) RFC 9110 `tchar`s, case-sensitive (`get` is not `GET`). Anything else, `CONNECT` (no tunnel lifecycle) and `HEAD` with a body are `E_INVALID_ARG`.
- curl mode: `HEAD` → `CURLOPT_NOBODY` (no body read, `Content-Length` kept in the headers); no body → curl's GET mode; any body → curl's POST mode (`POSTFIELDS`, read callback or `MIMEPOST`). `CURLOPT_CUSTOMREQUEST` carries every other method over that mode, so the body never depends on the method: GET may carry one, DELETE may send none.
- `UGO_BODY_NONE` sends no body and no `Content-Length`; a zero-length `UGO_BODY_MEMORY` sends `Content-Length: 0`.
- Automatically added headers: `Host`, `Content-Length` for a body, the generated `Content-Type: multipart/form-data; boundary=…` for a multipart body, and `Accept-Encoding: gzip` unless the caller sends a header of that name or the request has `UGO_REQ_RESUME` (*Content coding* above). curl's implicit `Accept: */*`, `Expect: 100-continue` (bodies over 1 MiB on HTTP/1.1) and `Content-Type: application/x-www-form-urlencoded` (non-multipart bodies) are suppressed unless the caller sends a header of that name, which then wins. No `User-Agent` unless the caller sets one. No automatic `Transfer-Encoding`: every body length is known before sending. With `UGO_REQ_RESUME`: `Range` for a non-empty file and `Accept-Encoding: identity` unless the caller sends `Accept-Encoding`. Caller overrides still apply. HTTP/2 converts the request to pseudo-headers and fields under its protocol rules (including removal of hop-by-hop headers).
- Speed: `max_recv_bytes_per_s` / `max_send_bytes_per_s` cap each direction (0 = none). `low_speed_bytes_per_s` with `low_speed_time_s` (whole seconds, curl's granularity; at most 65535, otherwise `E_INVALID_ARG`) aborts a transfer that moves fewer bytes per second than that for that long as `TIMEOUT`; both 0 = off, exactly one 0 = `E_INVALID_ARG`.

## WebSocket lifecycle

```
ws_open ─► CONNECTING ─[headers(101), handshake checked]─► OPEN ─ws_close─► CLOSING ─server CLOSE / close timeout─► CLOSED ─completed drained─► FINISHED ─release─► FREE
               │                                            │ server CLOSE: echoed ─────────────────────────────► CLOSED
               │                                            │ protocol error: we send 1002/1007/1009, stop reading ─► CLOSED once sent
               ├─ non-101: [headers] + completed(HTTP_STATUS) ───────────────────────────────────────────────► CLOSED
               └─ bad Accept/Upgrade/extension/subprotocol: completed(TRANSFER, WS_HANDSHAKE), no headers ────► CLOSED
   abort in any state before completed: no CLOSE frame, dropped at once ──────────────────────────────────────► CLOSED
```

- Handshake request: the caller's headers, curl's `Upgrade`, `Connection` and `Sec-WebSocket-Version`, and the library's `Sec-WebSocket-Key` (16 random bytes from PSA). A caller `Sec-WebSocket-Key` or `Sec-WebSocket-Extensions` header is `E_INVALID_ARG` (no extension is supported); curl's implicit `Accept: */*` is suppressed as for HTTP. A caller `Sec-WebSocket-Protocol` header offers its comma-separated values; several such lines add up.
- Redirects: a 3xx with a `Location` is followed by the shim, since curl fails every non-101 answer to an upgrade before its own follow logic. Each hop is a new connection with a new `Sec-WebSocket-Key`, up to 10 (`max_redirects` of the managed HTTP default; the WS request has no field). The target resolves against the current URL as curl resolves it for HTTP (`CURLU_URLENCODE | CURLU_ALLOW_SPACE`); `http`/`https` become `ws`/`wss`, any other scheme is `TRANSFER` / `CURLE_UNSUPPORTED_PROTOCOL`, an unparsable one `CURLE_URL_MALFORMAT`. `wss` → `ws` is followed as HTTP follows `https` → `http`. The caller's `Authorization`, `Cookie` and `Host` headers go only to the original scheme, host, port and IPv6 zone ID (the same filter as the 303 re-issue). After the 10th redirect a further 3xx is `TRANSFER` / `CURLE_TOO_MANY_REDIRECTS` with no `headers` event. `headers`, `ugo_result.headers`, `http_status` and the phase timings describe the last response (the refused 3xx on those failures); `redirect_count` counts followed hops and `redirect_us` sums their total times. `open_timeout_ms` spans every hop, `connect_timeout_ms` applies per hop.
- `headers` with status 101 is emitted only after the RFC 6455 §4.1 checks pass: exactly one `Sec-WebSocket-Accept` line and it matches the key, `Upgrade` is `websocket`, `Connection` lists `upgrade`, no `Sec-WebSocket-Extensions` line (an empty one included), and either no `Sec-WebSocket-Protocol` line or exactly one whose value equals one of the offered values (case-sensitive; with none offered any such line fails): on a ws id it means open, and `ws_send`/`ws_close` are accepted from the same moment. A failed check emits no `headers`; the 101 block is in `ugo_result.headers`.
- `open_timeout_ms` runs from `ws_open` until open; the library times it itself, because curl stops applying `CURLOPT_TIMEOUT_MS` to a `CONNECT_ONLY` transfer once connected.
- `completed` ends every socket. `ws_close_code`: the code of the first CLOSE frame, ours once fully written or the server's once fully read; 1005 if it carried no code; 1006 if no CLOSE was exchanged. `detail` is `WS_CLOSED_BY_LOCAL`/`_REMOTE` for that frame when the class is `NONE`, `TRANSFER` or `TIMEOUT`; `ABORTED` keeps `CALLER`/`SHUTDOWN` and a failed check keeps `WS_HANDSHAKE`. `ugo_result.error_message`: that CLOSE's reason for those three classes (its exact bytes, NUL included), else the error text.
- `completed.error_class`: `NONE` after a clean close handshake, and after a server CLOSE even if the server drops the connection before our echo lands; `DNS`/`CONNECT`/`TLS` for connect-phase failures, as for HTTP; `TIMEOUT` when the connect, open or close timeout fired; `ABORTED` on abort or shutdown; `TRANSFER` after a protocol error, a failed handshake check or a drop; `HTTP_STATUS` for a non-101 response, whose status and headers arrive in `headers`.
- Messages are text or binary, reassembled from fragments; each `ws_message` event carries its `type` (`UGO_WS_TEXT`, `UGO_WS_BINARY`, the RFC 6455 opcodes; `reserved` is 0). An invalid-UTF-8 text or an over-`max_message_bytes` message of either type gets 1007/1009: dropping it would break "nothing dropped". A server CLOSE with a 1-byte payload or a code an endpoint may not send gets 1002, one with an invalid-UTF-8 reason 1007; the class is `TRANSFER` also when that CLOSE answers ours. From the first such protocol error the owner reads nothing more from the socket, parses no further frame, sends its CLOSE (bounded by `close_timeout_ms`) and ends the socket as `TRANSFER` once it is written, without waiting for the server's. Framing errors that curl's decoder reports (masked frame, reserved bits or opcode, control frame over 125 bytes or fragmented, broken fragment sequence) end the socket at once as `TRANSFER`/1006 without a CLOSE (see debt.md).
- When we close because of a protocol error or answer a server CLOSE, queued messages that have not started are dropped; a message already partly written finishes first, since a frame cannot be cut. A local `ws_close` sends the queued messages before its CLOSE.
- PING is answered by a PONG with its payload (only the latest pending PING is answered); PONGs are ignored; nothing is sent after our CLOSE.

| Call | CONNECTING | OPEN | CLOSING | CLOSED / FINISHED | FREE |
|---|---|---|---|---|---|
| `ugo_ws_send` | `E_STATE` | `OK` / `E_CAPACITY` | `E_STATE` | `E_STATE` | `E_STALE_ID` |
| `ugo_ws_close` | `E_STATE` | `OK` | `E_STATE` | `E_STATE` | `E_STALE_ID` |
| `ugo_ws_release` | `OK` | `OK` | `OK` | `OK` | `E_STALE_ID` |
| `ugo_abort` | `OK` | `OK` | `OK` | `OK`, no-op | `E_STALE_ID` |
| `ugo_get_result` / `ugo_release` | `E_STATE` | `E_STATE` | `E_STATE` | `E_STATE` until `completed` drained, then `OK` | `E_STALE_ID` |

`ws_send`, `ws_close` and `ws_release` with the id of an HTTP transfer are `E_INVALID_ARG`; `ws_send`/`ws_close` after `ugo_abort` are `E_STATE`, after shutdown `E_SHUTDOWN`.

- `ugo_ws_open` checks limits synchronously (`E_INVALID_ARG`): `connect_timeout_ms`, `close_timeout_ms`, `max_message_bytes`, `max_backlog_count` > 0, `max_send_bytes` > 8, `max_backlog_bytes ≥ max_message_bytes`, and the one allocation (backlog, send buffer and per-message bookkeeping) at most `SIZE_MAX / 2` bytes. Backlog and send buffer are allocated there once.
- Backlog = messages emitted and not yet covered by `ugo_ws_release`, drained or not, plus the message being reassembled. In OPEN the owner reads the socket only while backlog messages are fewer than `max_backlog_count` and backlog bytes are below `max_backlog_bytes`; otherwise it stops reading (TCP back-pressure, control frames wait too). `max_backlog_bytes ≥ max_message_bytes` guarantees a partial message completes once the caller releases. In CLOSING it reads regardless of the backlog and drops data frames (RFC 6455 §7.1.1), so the server's CLOSE is seen.
- Messages carry `seq` = 1, 2, … per socket. `ugo_ws_release(ws_id, through_seq)` frees every message with `seq ≤ through_seq`; a `seq` above the last drained one → `E_INVALID_ARG`; an already released one → `OK`.
- `ugo_ws_send(type, data, len)` copies one message of `type` (`UGO_WS_TEXT` or `UGO_WS_BINARY`, else `E_INVALID_ARG`) into the send buffer (`max_send_bytes`, FIFO). Text that is not valid UTF-8 (RFC 3629: no overlong forms, surrogates or code points above U+10FFFF) is `E_INVALID_ARG`, checked in place without a copy. A queued message takes `len + 8` bytes of it (the library keeps each length and type inline): `len + 8 > max_send_bytes` → `E_INVALID_ARG`, not enough free room now → `E_CAPACITY`. No completion event: a send that never went out surfaces as the socket's `completed`.
- `ugo_ws_close`: `code` in 1000–1003, 1007–1014, 3000–4999; `reason_len ≤ 123` and valid UTF-8; else `E_INVALID_ARG`. The CLOSE frame is queued behind pending sends and takes no send-buffer room; `close_timeout_ms` runs from the call and bounds both the flush and the wait for the server's CLOSE. `abort` drops the socket without a CLOSE frame.

## Client lifecycle

```
create ─► RUNNING ─shutdown─► SHUT DOWN (drain, read, release) ─destroy─► gone
```

`ugo_client_shutdown`, in order: refuse `submit`, `ws_open`, `ws_send`, `ws_close` (`E_SHUTDOWN`; a call racing shutdown either takes effect before it, and its transfer is then finished below, or returns `E_SHUTDOWN` having changed nothing) → finish every transfer and socket (`ABORTED` / `SHUTDOWN`, no CLOSE frame) → join the owner thread without a timeout. `wait_events` is outside this barrier: blocked when shutdown starts or entered during it, it sleeps until events are present or the owner is joined; it returns the events it has, else `E_SHUTDOWN` once the owner is joined, else 0 on timeout. `abort`, `get_result`, `release` and `ws_release` keep working; after the join every slot is CLOSED/DONE, FINISHED or FREE, so the state tables answer them. Shutdown frees nothing: results and the pointers in leftover events stay valid until `ugo_client_destroy`.

## Threading

| Function | Thread rules |
|---|---|
| `ugo_monotonic_us` | Any thread, any time, no client |
| `ugo_client_create` | Any thread |
| `ugo_client_shutdown` | Any thread, concurrently with any call on the client; idempotent; every concurrent caller returns after the join |
| `ugo_client_destroy` | Any thread; shuts down if needed, then frees; no call on this client may be in flight or follow (C#: `SafeHandle.ReleaseHandle`). A pointer not in the process-wide live-client list (`NULL`, or already destroyed by `ugo_shutdown_all`) is a no-op |
| `ugo_shutdown_all` | Shuts down and destroys every client of the loaded library; returns how many. Only while no `ugo_*` call is in flight; once per domain before its first `create` |
| `submit`, `abort`, `release`, `get_result`, `ws_*` | Any thread, concurrently; never wait on network or on the owner's work, only on short internal locks |
| `ugo_wait_events` | Any thread; one drainer per client at a time, a concurrent second gets `E_BUSY`. `timeout_ms = 0` polls; every timeout is finite, so a drainer never sits in native code past it (an unloading domain waits for its threads); returns 0 on timeout. `capacity = 0` → `E_INVALID_ARG` |

The library never calls into the caller. Using a returned pointer concurrently with `ugo_release`/`ugo_ws_release` of it, or with destroy, is the caller's race.

## Ownership

| Pointer | Owner and lifetime |
|---|---|
| `ugo_client*` | Library; valid until `ugo_client_destroy` or `ugo_shutdown_all` |
| `config`, `request`, `ws_request` structs, the `ugo_mime_part` array | Caller; read only during the call |
| `url`, `headers`, `sink_path`, file `body`/part paths, part `name`/`filename`/`content_type`, `ca_bundle`, `ws_send` data, close `reason` | Caller; copied during the call |
| Memory `body`, `UGO_PART_MEMORY` part `data` | Caller; borrowed (unchanged, alive) until that transfer's `completed` is drained or `ugo_client_shutdown` returns; copied for a detached transfer |
| `events` buffer | Caller; written by `wait` |
| `headers.headers`, `ugo_get_result` views | Library; until `ugo_release(id)` or destroy |
| `ws_message.data` | Library; until `ugo_ws_release` covers its `seq`, `ugo_release(ws_id)` or destroy |

The library frees only its own memory, the caller only its own. Destroy may discard undrained events: exactly-once is about emission, so the managed side releases what it holds for each transfer (pins of borrowed bodies) when `shutdown` returns, not on a `completed` it may never drain.

## Choices the docs left open

1. Addresses in structs are `uint64_t`, not pointers: one layout on every ABI, armeabi-v7a included, so one check table and no per-ABI C# variants.
2. Every 8-byte field is 8-aligned by explicit `reserved` fields: the layout does not depend on whether a compiler or runtime aligns `int64` to 4 (i386, some 32-bit Mono) or 8.
3. Events are one 128-byte struct (24-byte header + 104-byte union); C# holds the union as `fixed ulong u[13]` and reinterprets it per `kind`: one array type, no `Explicit` layout.
4. Client handle is a pointer; shutdown and destroy are separate: shutdown is safe under concurrent calls, destroy needs none in flight, which `SafeHandle` already guarantees.
5. Orphans of a previous domain are handled by `ugo_shutdown_all()` at domain init: no domain tag in the ABI, Unity has one domain at a time.
6. ABI version is checked only through `config.abi_version` at create (`E_ABI`, exact equality): plugin and C# ship together, no separate export, no compatibility shims.
7. Every transfer, WebSocket included, ends with exactly one `completed`, which also carries the close code: one terminal path for slot bookkeeping.
8. Header block travels in the `headers` event (a view valid until release), so no getter is needed while the body is still running.
9. HTTP and WebSocket request headers are `\n`- or `\r\n`-separated lines. A line starting with SP or HTAB (including an obsolete folded continuation), holding NUL, or holding a CR not directly before its LF (a CR ending the block included) is `E_INVALID_ARG` (RFC 9110 §5.5). Other lines are passed to curl as is: `Name:` removes a curl default header, `Name;` sends an empty one.
10. The method is a token, not an enum: new or custom verbs need no ABI change. Whether a body-less method sends `Content-Length: 0` is the caller's choice (`UGO_BODY_NONE` vs an empty memory body); the C# layer applies HttpClient's rule.
11. `completed.detail` instead of new classes: the class list is the contract's, but retry policy differs for abort vs shutdown vs background expiry, and memory limit vs a cut connection.
12. File sink truncates an existing file instead of `O_EXCL`: the caller owns naming, and a `.part` left by a crashed run must not fail every retry.
13. `connect_timeout_ms` and `close_timeout_ms` must be > 0 (`E_INVALID_ARG`), `total_timeout_ms`/`open_timeout_ms` 0 = none: no hidden curl defaults (300 s connect). Other zeros: `max_transfers` 0 → `E_INVALID_ARG`; `memory_limit` 0 with a memory sink → `E_INVALID_ARG` (the contract forbids silent growth; ignored for a file sink or a detached transfer); `max_recv_bytes_per_s`/`max_send_bytes_per_s` 0 = no limit; `low_speed_*` both 0 = off; `max_redirects` 0 = follow none, a 3xx is the final response (`HTTP_STATUS`).
14. `dns_cache_ttl_s` (0 disables curl's cache) and `max_total_connections` (0 = unlimited) are per client: one value per client, applied to every easy handle.
15. CA bundle override (PEM, copied) is per client at create, not per request or mutable: a new bundle means a new client, no locking on the hot path. Parsing starts on the client's first TLS connection; only a successful parse is cached. On any parse failure the partial chain is freed, the PEM is kept for the next connection, and the current connection fails: explicit allocation errors return curl 27 (`CURLE_OUT_OF_MEMORY`), other failures return `TLS` (curl 58, `CURLE_SSL_CERTPROBLEM`) with a message naming the bundle. A partly parsed bundle is refused whole; a malformed bundle is reparsed and fails on every TLS connection. `create` still returns `OK`, as before.
16. `UGO_CLIENT_TLS_INSECURE_DEV` exists in the header for both build kinds; a release build treats it as an unknown bit (`E_INVALID_ARG`), so the C# side needs no build-dependent layout.
17. `http_version` uses 10/11/20 (`UGO_HTTP_*`), not curl's values: no curl types or values in the ABI. The version is not selectable: curl's default (HTTP/2 over TLS via ALPN, HTTP/1.1 cleartext) is what the contract asks.
18. Detached transfers copy memory bodies and refuse a file sink: without `completed` the caller cannot know when a borrow ends or whether the file is whole. They still take a slot and return an id, so `abort` works and the slot bounds how many run at once.
19. The event clock counts system sleep on every platform: one meaning everywhere, and a deadline that spans a device sleep fires on wake, when the connection is most likely dead. App pause is the caller's to subtract, measured with `ugo_monotonic_us`.
20. A stale client pointer is not guarded against address reuse: `destroy` matches by address, so a late `destroy` of a pointer freed by `ugo_shutdown_all` could hit a newer client at the same address. Unreachable in Unity: the old domain's code (finalizers, drainers with finite timeouts) has stopped before the new domain's first `create`, and an IL2CPP player has no domain reload.
21. The `CURLcode` → class table (`error_class` in `native/src/ugo.c`) is a switch over every code of the pinned curl with `_Static_assert(CURL_LAST == …)`: a curl bump fails the build until the table is reviewed. The shim's own callbacks override it (memory limit, local IO, abort/shutdown). `URL_MALFORMAT`/`UNSUPPORTED_PROTOCOL` can only come from a redirect target and are `TRANSFER`. `WRITE_ERROR` is `TRANSFER`: the shim's write callbacks set their own class (`LOCAL_IO`, memory limit), so a bare one comes from curl's content decoder.
22. One `ugo_ws_send` with a `type` argument instead of a second export for binary: one P/Invoke, one validation path, and the type travels with the length in the 8-byte header each queued message already carries, so a binary send costs no extra send-buffer room.
