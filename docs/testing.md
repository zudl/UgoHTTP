# Testing

Agents cannot see a device; tests can. A scenario below counts as library coverage only where it runs through `libugo`, and each disputed one names the level or gate step that checks it. The bench and container selftests drive the system `curl` and check the test stand, not the library. Gaps found so far are listed in `docs/debt.md`.

## Levels

| Level | What | Where |
|---|---|---|
| Native unit | C shim: queues, lifecycle, abort, file sink, write errors | Linux container on the Mac (ASan, TSan, UBSan, LSan); macOS (ASan+UBSan, TSan) |
| Fault bench | a local scripted server (below) that the native, .NET, Unity and player tests run against; gate step `bench` runs `tests/bench/selftest`, which checks each endpoint with the system `curl`: a check of the bench, not of the library | Linux container for all scenarios; macOS, Android emulator, iOS simulator for unprivileged ones |
| Container faults | gate step `container` runs `tests/container/selftest`: iptables, `tc netem`, dnsmasq and tmpfs fault injection checked with the system `curl` and one direct-libcurl `ugo-smoke` probe. A check of the fault tooling, not library coverage; the library-level fault tests are native tests run in the container (`container-native-asan`, `container-native-tsan`) | Linux container on the Mac |
| .NET unit | C# core without Unity: API, event decoding, threading | `dotnet test` on Mac, Linux container |
| Unity EditMode | Unity glue, edit-time request and WebSocket echo/close (both drain modes, both API forms) with no Play Mode and nothing pumping, a transfer and an open WebSocket surviving Play Mode enter/exit, domain reload mid-transfer and with open WebSockets in both drain modes, orphaned client after reload, quit hook, tracker window rows (released row greyed, selection, search, stack links) and its layout and sort across a reload, leaks marked at Play Mode exit, concurrency stress under Mono, P/Invoke under Mono | Editor batchmode on macOS; Windows open (no Windows machine) |
| IL2CPP player | layout dump, HTTP checks (gzip over HTTP/2 included), `detached_post` (UTF-8 POST with a custom header, finish-in-background, 15 s connect / 25 s total timeout; runners require the full body SHA-256 and header on the bench) and a WebSocket echo/close (listener over ws, awaitable over wss) in a built player (plain app, result as one `UGO-RESULT` JSON line; project `tests/player`; runners `tests/android/run`, `tests/ios/run`); on iOS also finish-in-background and its expiry, with `background_detached_post` sending a throttled POST to a slow response in the same background cycle and the runner requiring its full body and header to arrive while backgrounded | Mac: own arm64 AVD `ugohttp_player`, own iOS simulator `ugohttp_player` (arm64). CI (planned): x86_64 AVD |
| Device | physical low-end and flagship Android, physical iPhone | manual or device farm |
| WebSocket soak | `tests/ios/run --soak <seconds>` (with `--device`: the phone; without: the simulator): the player opens two wss sockets to the bench's `/ws/soak`, one per API form, under one client. The bench pushes numbered messages (10/s, a burst of 100 every 30 s, every 300th 70 000 bytes), pings every 10 s (PONG is the library's), checks and echoes the player's numbered messages (5/s per socket, every 300th 100 000 bytes); a message's bytes follow from its number, so each side checks every byte. A mismatch, a missing pong, a drop or any close before the player's own 1000 fails the run (no reconnect). Every minute a `UGO-SOAK` line: counts and bytes each way, mismatches, send-buffer-full count and longest streak, managed heap after a full collection, GC count (the minute's own collection included, so one a minute means nothing else allocated enough to trigger one), resident size and physical footprint (`task_info`); the runner's summary adds the bench's view per socket and first/last/min/max of each memory series | manual, not in the gate: 4 h on the iPhone |

## Invariants checked by every library-level scenario

- Exactly one `completed` per transfer, in every phase it can be aborted in.
- No access to freed memory (sanitizers).
- The error class is the expected one, not just "failed".
- No `.part` left behind unless the request asked to keep it.

## Scenarios

Unless a line names another level, a scenario is checked by the native tests (`native-asan`, `native-tsan`, `container-native-asan`, `container-native-tsan`) against the bench.

- **DNS** (native, in the container only): on one long-lived client with a DNS cache TTL of 0, NXDOMAIN and SERVFAIL are `Dns` and the same name resolves again once DNS is back (negative-cache regression).
- **Connect:** blackhole (no SYN-ACK) is `Timeout` within the connect timeout (300 ms, asserted under 1 s; native, in the container); a refused port is `Connect` (native); offline → online on the same client (IP literal, no DNS; native, in the container). Slow connect is checked by the container selftest only.
- **TLS:** a valid chain from a foreign root and a malformed or partial CA bundle are `Tls` (native `tls_untrusted`); a TLS 1.2 roundtrip (native); self-signed is `Tls` in the IL2CPP players. Expired, wrong hostname and incomplete chain endpoints are checked by the bench selftest only. Public hosts (and `wrong.host.badssl.com` from the Linux and Windows probes) only with `./scripts/verify --online`: manual, not in the gate. Revocation is not tested.
- **AES-GCM:** SP 800-38D vectors and fixed outputs of stock mbedTLS for 63–129 and 16384-byte payloads, AES-128 and AES-256, encrypted and decrypted in place through PSA (native `aes_gcm_known_answers`, no bench; guards the patched GCM path, patches.md).
- **Response:** headers then stall; slow but moving body; cut mid-body; wrong `Content-Length`; chunked.
- **Status:** 408/429 with `Retry-After` (bench selftest only); 5xx; 301/302/307/308 with JSON and multipart POST (method and body replay, identical bytes); a non-2xx body for a file request, under and over the 64 KiB cap.
- **303:** POST and PUT with a memory, file, multipart or caller-chunked body become a GET without body, `Content-Type`, `Content-Length`, `Content-Encoding` or `Transfer-Encoding`, other headers kept, HEAD stays HEAD (HTTP/1.1 and HTTP/2, native; POST with a managed body, .NET); 303 → 302 → 200 and 302 → 303 → 200; `Authorization` and `Cookie` dropped for another origin; a caller `Host` kept for the same origin and replaced by the target authority for another, as after a 302; a total timeout above `INT32_MAX` ms; `connection_reused` false when the first segment opened the connection; the redirect limit counts curl's hops and the re-issue together (`TOO_MANY_REDIRECTS` one hop short); HTTP/2 keeps the connection; file sink, resume (HTTP/1.1 and HTTP/2) and detached across a 303; `max_redirects` 0 delivers the 303.
- **Header lines:** NUL, a bare CR and a CR ending the block are `E_INVALID_ARG` for `submit` and `ws_open`; mixed `\n`/`\r\n` blocks pass.
- **Methods and headers:** HEAD (no body read, `Content-Length` kept), PUT/PATCH/DELETE/GET with each body kind, OPTIONS, custom and lower-case tokens; malformed tokens and CONNECT rejected; the recorded request headers are exactly the caller's plus `Host`/`Content-Length`/multipart `Content-Type`, and `Accept-Encoding: gzip` unless the caller sent an `Accept-Encoding`.
- **Content coding:** gzip and deflate over HTTP/1.1 and HTTP/2 decoded to memory and to file, after a redirect; a caller `Accept-Encoding` (a value or a removal line) gets the encoded bytes; corrupt data, an unknown coding, bytes after the stream and a stream cut in its header, payload or trailer (gzip, zlib-wrapped and raw deflate; `Content-Length`, chunked, HTTP/2; memory, file, `KEEP_PARTIAL`) are `Transfer`, while an empty body with `Content-Encoding: gzip`, an empty gzip stream, the ignored encoded body of a followed redirect, 204, 304 and HEAD are not; the memory cap and the 64 KiB error-body cap of a file request count decoded bytes; headers, progress and `bytes_received` count encoded ones; a resumed download stays undecoded, with or without a caller `Accept-Encoding`; HEAD and 204.
- **Speed:** upload cap stretches a transfer; a body below the minimum speed for the stall timeout ends as `Timeout`; with the stall timeout alone a body at 500 B/s that takes longer than the timeout succeeds and a silent one ends as `Timeout`.
- **Parallel:** 5+ downloads over HTTP/1.1 and HTTP/2; abort in DNS, connect, TLS, headers, body.
- **Lifecycle:** abort racing a successful finish (one `completed`, result kept); abort, release and double release with stale ids; submit with no free slot fails at once.
- **Events:** `headers` after redirects and for 204; progress only on byte change; intermediate progress publications at most once every 10 ms per transfer; any held count published before `completed`, regardless of the interval; metrics present in `completed`.
- **ABI:** `config.abi_version` mismatch → `E_ABI`; `sizeof`/`offsetof` of every struct equal in C and C# (gate step `abi-layout`; IL2CPP layout dump in the players).
- **WS control:** lone PING, split PING, control frames between fragments (text and binary), bad, repeated or missing `Sec-WebSocket-Accept`, any `Sec-WebSocket-Extensions` (empty included), a `Sec-WebSocket-Protocol` not offered, not among the offered values, empty, repeated or differing in case (a matching one opens), a caller `Sec-WebSocket-Extensions` rejected, server CLOSE answered, 70 KB frame, partial send (a slow-reading server; a stalled one fills the send buffer), slow consumer pauses receive (the server's flood is held back, nothing dropped, order kept); during a flood of PONGs a close with a short timeout, an abort and a parallel HTTP request on the same client all complete; during a flood of empty outgoing messages a parallel GET and an abort on the same client both complete.
- **Detached:** many detached posts emit no events and free their slots; abort of a detached id works until it finishes; a full client rejects a detached submit.
- **iOS background:** a transfer with finish-in-background completes after the app is backgrounded; a stalled one is aborted as `ABORTED`/`BACKGROUND_EXPIRED` when iOS expires the task (about 30 s) and the app is then suspended, not killed. Simulator in the gate (`ios-player`); device manual.
- **Threads:** submit, abort and drain from several threads at once under TSan; shutdown while transfers are in flight; nothing drains during a long transfer → it still completes, progress coalesced, `completed` not lost.
- **File:** disk full on write and on close (small tmpfs, native in the container); abort removes `.part`.
- **Resume** (bench `/range/<size>`: strong `ETag`, `If-Range`, `cut=` mid-body and `bps=` over HTTP/1.1 and HTTP/2, `mode=` for every misbehaving ranged answer, `gzip=1`): cut then resume gives bytes identical to an uninterrupted download (native and .NET, HTTP/1.1 and HTTP/2, IL2CPP players), `Range` and `Accept-Encoding: identity` on the wire, also across a redirect, whole-file progress and `resume_offset`; a `200` from a server ignoring the range and an `If-Range` mismatch rewrite the file; a matching `If-Range` and an unknown total (`/*`) append; a short `206` fails `TRANSFER` and repeated resumes finish the file; `416` for a complete file succeeds untouched, one with a body over 64 KiB is `MEMORY_LIMIT`; a `206` starting elsewhere and a `416` shorter than the file delete it as `RESUME_MISMATCH` (over HTTP/2 too), unless `KEEP_PARTIAL`; no, repeated or malformed `Content-Range`, multipart, a `Content-Length` other than the range, a body short or long of it (chunked, close-delimited, HTTP/2 without length), a huge `Content-Length`, and a `416` longer than the file fail and keep the valid prefix; an abort while appending keeps the file; no file or an empty one sends no `Range`; a non-2xx and a cut leave the file; `HEAD`, a caller `Range` and a missing sink are rejected.
- **Pause:** event timestamps stay monotonic across app pause/resume. Not tested: the native test checks the clock across a sleep only.
- **WS:** Bearer handshake (ws, wss over an HTTP/1.1-only and an h2-capable TLS endpoint), refused handshake delivered with status and headers, redirects followed (301/302/303/307/308, an absolute `https` target, a chain of 10, the 11th refused as too many, an unsupported scheme, `wss` → `ws` and to another port with `Authorization` dropped), open timeout, fragmented messages, ping/pong, server close, binary messages both ways (empty, 70 KB, non-UTF-8 bytes, fragmented by the server, interleaved with text; native, .NET listener and awaitable, Unity EditMode, IL2CPP players), invalid UTF-8 text refused on send, invalid UTF-8 (1007) after which a later message is not delivered and the socket ends without waiting for the server's CLOSE, oversize message (1009); after invalid UTF-8, an oversized fragmented binary message and a malformed server CLOSE the server gets exactly one CLOSE (1007, 1009, 1002) and a frame curl's decoder would refuse, sent in the same write, is never read; close timeout, abort while connecting, open and closing (no CLOSE sent), shutdown, sends from another thread under TSan, exactly one `completed` in each; managed: listener and awaitable forms, no allocation per text or binary message in a listener; reconnect is the caller's; 4 h soak (*WebSocket soak* above).

The bench server binds to port 0, so parallel runs never collide.

## Tooling

`out/gate/` retains the 10 most recently finished runs (identified by `summary.json`), leaving unfinished runs untouched; iOS DerivedData is reused in `out/ios-player-derived/`, and bench run directories are deleted on clean server exit and retained on failure.

- **Fault bench:** Python (asyncio, h2, wsproto, trustme), no web framework; dependencies locked with hashes by `uv`, one venv per worktree. Listeners on port 0, one JSON `ready` line after every endpoint is bound.
- **Privileged scenarios** (SYN blackhole, slow connect, NXDOMAIN/SERVFAIL, offline → online, disk full): a throwaway Linux container per run with `NET_ADMIN` — iptables, `tc netem`, its own dnsmasq, a small tmpfs. The image and test binary follow the host's architecture (`tests/container/platform`: Linux arm64 build and `packages.lock` on the Mac, Linux x86_64 and `packages-amd64.lock` on a Windows x64 host), so they always run natively: sanitizers and `tc` faults are not trusted under QEMU user emulation. Never change the Mac's own network, DNS or firewall.
- **Unity:** small test project in `tests/unity/` referencing the package by local path; Unity Test Framework in batchmode (`-runTests`, NUnit XML, never `-quit`). A domain reload inside a test is `EditorUtility.RequestScriptReload()` + `yield return new WaitForDomainReload()` in a `[UnityTest]` (works in batchmode on 6000.3); the code after it runs in the new domain on a fresh enumerator, so state crosses in `SessionState` and a file under the project's `Temp/`, and `AppDomain.DomainUnload` marks the point the old domain went away. Player tests run from the Unity project `tests/player/` (package by local path, only the `androidjni` and `jsonserialize` modules): `tests/android/run` builds nothing itself, installs the IL2CPP APK on its own AVD in a free emulator slot, reaches the bench through `adb reverse` on 127.0.0.1 and reads one `UGO-RESULT` JSON line from logcat. `tests/ios/run` builds nothing either: it creates (once) and boots its own simulator `ugohttp_player` (runtime and device type pinned in `scripts/versions.env`; `error` if it is already booted), waits on `simctl bootstatus`, passes the bench config as `SIMCTL_CHILD_UGO`, reads the app's console (`simctl launch --console-pty`), sends the app to the background on `UGO-BACKGROUND-READY` by launching Settings, brings it back after the expiry line, and shuts its simulator down. It also streams the simulator's runningboardd lines about the player: an attempt in which runningboardd killed the player (`0x2182BAD2`) for a background assertion whose expiry warning reached the player less than 1 s before the expiry, or not at all (iOS schedules it 5 s ahead; UIKit runs expiration handlers only once it arrives), is run again, up to 3 attempts, each with a fresh bench, and listed in `late_expiry_warnings`; three such attempts are `error` (overloaded host), any other early end is `fail`. The simulator shares the host network, so the bench is reached on 127.0.0.1. With `--device <udid>` (and `--team <id>` to build and sign the player itself: `IosPlayerBuild.Build -ugoDevice`, `xcodebuild` for `iphoneos` with automatic provisioning) it runs on a USB device instead: the bench listens on this Mac's LAN address (`--bench-host`, default the default-route interface; `scripts/bench --host` also puts it into the https certificate), `--keychain` names an unlocked keychain holding the signing identity; `ios-deploy` installs the app and launches it under lldb with the config in the `UGO` environment variable and relays its console (under a pseudo-terminal from `script`, else lldb's Python holds the lines until exit); the player opens Settings itself on `UGO-BACKGROUND-READY`. Under the debugger the app is not suspended, so the result arrives without anyone bringing it back to the front; the phone must stay unlocked for the launch. Not a gate step: it needs a signing identity, an unlocked phone, and, once per install, the person trusting the developer on the phone (free team) and allowing iOS's local network prompt. The gate steps `android-player` and `ios-player` build the player from `tests/player` first (`AndroidPlayerBuild.Build`; `IosPlayerBuild.Build`, then `xcodebuild` for the simulator SDK), never the native libraries: those come from `./scripts/build` and are only checked for staleness. The iOS test player builds with Unity audio disabled: an active audio session keeps the app running in the background, so no suspension or expiry would happen.
- **Test apps show their state on screen:** a Unity test app (`tests/player` and any later one) shows its mode, current check, counts and verdict (soak: elapsed and remaining time, messages each way, mismatches, last resident size) in a readout that only reads state the checks already keep, from the main thread, rebuilt at most once a second: no locks the checks wait on, no work on their threads, no per-frame allocation.
- **Windows without Windows:** `verify windows-x64` runs Wine 10 in a `linux/amd64` container and `verify windows-arm64` in a `linux/arm64` one, native on the Mac (`tests/wine/`, both built by bootstrap, `--network none` unless `--online`; on a Windows x64 host the x64 probes run natively and windows-arm64 gets the static checks only, see debt.md *Windows host coverage*): `ugo-smoke.exe` (the same version/protocol/feature probe as Linux; public TLS with `--online`) and `ugo-dll-probe.exe`, which loads the shipped `ugo.dll` by path, resolves every export with `GetProcAddress` and, through those exports only, fetches from an in-process HTTP server via `localhost` (threaded resolver) and starts a TLS handshake against it that must fail as `TLS`; with `--online` it fetches `https://example.com` (HTTP/2) and expects `TLS` from `wrong.host.badssl.com`. The native unit tests do not run there: they are POSIX (pthreads, `unistd.h`, `fcntl`) and need the bench, which binds the Mac's 127.0.0.1 with certificates for loopback names only.
- **Emulators:** waits are on real readiness (`sys.boot_completed`, `simctl bootstatus`), every command names its serial/UDID, nobody shuts down a device they did not start.

## CI matrix

No CI runs yet: releases are cut locally after a full gate (decisions.md *Unity package delivery and releases*), and the gate runs one Unity Editor, 6000.3. The artifact and package checks below already run in the gate; CI adds the per-change trigger, the second Unity version and the x86_64 AVD.

- Native build per change: Android (3 ABIs), iOS (device + simulator), macOS universal, Windows x64 + ARM64, Linux x64 + ARM64; `./scripts/package` assembles the `upm` tree from those builds (gate step `package`: twice, identical `tree_sha256`).
- Artifact checks: 16 KB alignment; only `ugo_*` exported (iOS: only `ugo_*` global, no named local symbol, an app links it next to a second curl/mbedTLS/nghttp2/zlib without clashes; Windows: PE export table, and only the pinned system DLLs imported); curl/TLS/nghttp2/zlib versions match the pins and curl lists `libz` (runtime probe on macOS, Linux and Windows, Linux x86_64 under emulated `linux/amd64` docker, Windows x64 under Wine in that docker, Windows ARM64 under Wine in `linux/arm64` docker, macOS x86_64 under Rosetta; archive strings on Android and iOS); `libugo` size per ABI under `LIBUGO_MAX_BYTES` (`scripts/verify`).
- Unity: 6000.3 LTS and the newest supported 6.x (the second version is planned); IL2CPP players for Android and the iOS simulator.

## Benchmark against other clients

Clients: `UnityWebRequest` (the baseline), `System.Net.Http.HttpClient` with Unity's default handler, and `HttpClient` over Cysharp's YetAnotherHttpHandler (native hyper + rustls).

Same scenario, same device, release builds: 5 parallel downloads of ≥ 20 MB each to file, on a normal and a throttled disk.

Metrics: throughput, CPU % per thread, main-thread ms per frame (target: only enqueue and drain), managed allocations, native RSS/PSS, recovery time after a network switch and after offline → online, APK/IPA size delta.

Manual, not in the gate: the benchmark app lives outside the repo (decisions.md *Plugin staging and player tests*).

Pass: no worse than UWR on CPU and throughput; fewer managed allocations. RSS is reported, not a pass criterion (decisions.md *Size and performance against UnityWebRequest*).
